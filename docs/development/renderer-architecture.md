# Portable card renderer

Renderer version 6 consumes the stable self-contained version-1 field payload. Setup copies
`src/akb/web/renderer.js` into selected front/back templates and `renderer.css` into
synced note-type styling. Review requires no master database, Python, library,
module loader, remote font, network request or media-file installation.

## Modules and markers

`setup.py` plans field selection, ownership, collisions and application;
`cleanup.py` plans removal and safe clearing. `dialogs.py` is a Qt form around
QueryOp/CollectionOp; it does not implement bulk generation. `integration.py`
handles lifecycle and the Tools submenu. Tiny collection-local mappings refresh
after operations/undo and before note serialization. This never scans or regenerates
notes in a post-save hook.

HTML markers enclose the container, JSON data element and executable renderer:

```html
<!-- AKB:START owner=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa renderer=6 -->
<div class="akb-root" data-akb-owner="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" data-akb-theme="classic">
<script type="application/json" class="akb-data">{{Auto Kanji Breakdown}}</script>
</div>
<script>/* installed vanilla renderer */</script>
<!-- AKB:END owner=aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa -->
```

Styling uses equivalent `/* AKB:START owner=… renderer=6 */` / `/* AKB:END owner=… */`
markers. A full 32-character hex token and matching end are required. Exactly zero
or one block is allowed per side/style. Partial, duplicate, nested or unknown-owner
markers cause refusal. Intact moved blocks are recognized. Only the matched span
changes; no outside newline is appended, normalized or removed. Renderer version
is independent of master/payload versions. Setup safely replaces outdated blocks
after preview. Status reports missing/current/outdated/damaged integration.

Keep markers intact when moving a block. Put custom `.akb-root` CSS variables
outside owned styling; inside edits are replaced on setup. All styling is scoped.
Eight explicit palettes use custom properties in one stylesheet: Light, Dark,
Blue (default indigo), Brown, Matcha, Matcha Dark, Sakura and Sakura Dark.
Saved identifiers retain `classic` for Blue and `sakura` for Sakura Dark.
Appearance is stored as a mapping `theme` and an allowlisted `data-akb-theme`
attribute inside the synced owned template. No theme is stored in note payloads.
Changing Anki's night-mode state does not override an explicitly selected palette;
no Follow Anki mode is claimed across clients. Unspecified themes use Blue.

Opening Setup and applying its review safely upgrades intact version-1 blocks to
version 6. Existing owner tokens are retained, and outside bytes are untouched.
Missing/new theme records default to Blue; malformed/unknown saved names have a
Blue presentation fallback, while direct template requests reject unsupported
values. Theme-only changes do not recommend or require payload regeneration.
Cleanup continues using the same owner/version-independent marker recognition.

## Safe field expansion

The serializer escapes `<`, `>` and `&` as JSON Unicode escapes before
saving. A real Anki backend test verifies template expansion retains those bytes,
including malicious-looking meanings and literal template braces. JSON is never
embedded in an attribute. The renderer reads the JSON element's `textContent`,
parses it and writes all strings with DOM `textContent`. Payload values never become
HTML, URLs or executable code.

Empty/malformed/unsupported payloads leave an empty hidden container. Shape, depth
and node-budget checks reject malformed trees. The safe-script boundary assumes
generated bytes came through the serializer; manually inserting raw unescaped
HTML/script into a template-expanded field is outside that contract. Setup refuses
noncanonical existing field content. Source/dictionary strings use the serializer.

Mounting is idempotent. When FrontSide includes a front block and the back has its
own block, the last same-owner container wins. Queries only inspect owned roots;
there is no card-wide text scraping. Client-specific lifecycle behavior remains
part of actual Anki/mobile smoke testing.

## Display policy

Compact slate cards, large Japanese serif glyphs, reading chips, lavender meanings
and green radicals follow the supplied screenshot. Light mode uses pale surfaces
and purple/green accents. Fonts are local Japanese system stacks; glyph coverage
depends on the device. The renderer never changes unrelated card backgrounds.

Main meanings and readings remain complete in the payload. By default, each reading
group shows a source-order prefix of at most four readings / 26 Unicode code points
(including separators); main meanings show at most four senses / 90 code points.
The first item is always retained whole even if it alone exceeds the budget.
Short lists stay fully visible. A small `+N` button reveals all remaining entries,
then offers Less. No dictionary values are changed or discarded.

Empty reading groups and missing frequency are omitted. Frequency displays as
`Freq #N` with a Frequency rank title/accessible label. Root radicals highlight the
main glyph and a labelled star without an invented child.

Main structure and nested branches start collapsed. Clicking/tapping noninteractive
parts of an expandable card toggles its main structure. A native main chevron button
provides keyboard Enter/Space activation and `aria-expanded`; the containing section
is not a button, avoiding nested-button semantics. Nested buttons and full-list
controls stop click propagation. Selection drags do not toggle the card. Child links
and input controls are ignored by the whole-card handler. Structureless entries have
no structural expander or pointer cursor, though long lists can still be revealed.

Chevrons are small CSS strokes inside transparent 40px controls (44px on coarse
pointers), not dark square tiles. Main toggles stay at top right. Trees use light
one-pixel lines, compact rows, smaller deeper glyphs and reduced indentation after
three levels. Lightweight hover/pressed feedback and chevron transitions respect
reduced-motion preferences. Variants display actual `char`, keeping glosses resolved via `base`.
Only general radicals highlight; `phon` remains in payloads and is not displayed.
Transparent/part groups create no visible blank nodes; descendants remain reachable.

### Component glosses

Rules are deterministic and presentation-only:

1. Keep nonempty string meanings in source order; trim whitespace.
2. Separate phrases containing `radical (no. N)` or `radical variant (no. N)`.
3. Exclude numerical/dictionary senses containing digits, “counter for”, “ordinal”,
   “numeral” or “trigram”. Prefer the first remaining plain meaning in source order.
4. Only if no plain meaning exists, strip a terminal radical suffix and split the
   remaining ` or ` phrase. Suppress positional “left/right/top/bottom village”
   labels and take at most two unique phrases.
5. Omit the gloss if nothing useful remains.

Thus 聿 shows **brush**, ⻖/阜 **hill**, 京 **capital**, and 廴 **long stride; stretching**.
Source order is a transparent heuristic, not semantic ranking. No manual meaning
dictionary is added. Master/payload arrays and full main meanings are unchanged.

### Positions

The centralized JavaScript map follows [the supplied-source audit](rendering-policy.md).
Raw codes remain unchanged in payloads:

| Raw | Display |
| --- | --- |
| left, right, top, bottom, middle | left, right, top, bottom, middle |
| nyo | lower-left |
| tare | upper-left |
| kamae | enclosure |
| nyoc, tarec, kamaec | inside |
| ⿵A | upper enclosure |
| ⿵B | inside |
| ⿶1 | inside |
| ⿶2 | lower enclosure |

Recognized visible-node position wins. Otherwise exactly one `via` context with a
recognized position can supply a label. Multiple contexts are ambiguous, even when
their codes coincide: omit the badge. No via node is rendered, no internal chains
are concatenated, and hidden radical metadata is not assigned to a descendant.
Unknown positions are omitted. Labels express source relationships, not geometry.

## Verification boundary

Desktop Edge/Chromium tests exercise DOM/CSS at 820px and 360–430px, keyboard/touch expansion,
malicious-looking strings, idempotence and no network. They do not verify Anki's
embedded WebViews or actual mobile apps. Synced templates/CSS/payloads are designed
to render offline on AnkiMobile and AnkiDroid. The maintainer has confirmed mobile review after sync; exact client versions,
fonts, night modes and offline checks remain in the [manual checklist](testing.md).
Mobile cannot run the Python generator; source edits need desktop regeneration.
See [testing](testing.md) for actual-client checks.


## Sources panel (renderer 6)

One collapsed native **ⓘ** button sits at the bottom-right after all kanji cards in each root.
It toggles inline offline attribution with aria-expanded, keyboard Enter/Space,
and a 44px coarse-pointer target. Its events do not toggle kanji cards. Text and
HTTPS links are fixed trusted renderer constants, with snapshot values passed
through textContent after shape checks. It credits KANJIDIC2/James William Breen/
EDRDG (CC BY-SA 4.0), KanjiVG/Ulrich Apel and contributors (CC BY-SA 3.0), and
Nik Dhanda's compilation/transformation (combined adaptation CC BY-SA 4.0).
No endorsement is implied. Optional payload provenance identifies that breakdown's
actual snapshot; legacy data reports details unavailable. Rendering fetches nothing.

The footer inherits the existing eight palettes; the card layout, branch lines,
reading sizes and spacing are otherwise unchanged. Existing owned renderer 1/2
blocks upgrade through Setup or theme Apply, without regenerating payloads.
Desktop database updates never alter templates. See [database updates](../database-updates.md).
